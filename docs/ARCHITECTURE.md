# 아키텍처 원칙

## 문서 목적

이 문서는 Unity 6000.3.21f1 프로젝트의 코드 경계와 의존성 규칙을 정의한다.

## 설계 목표

- 같은 전투 입력과 난수 시드가 같은 결과를 만든다.
- 족보와 피해 공식을 화면 없이 테스트하고 시뮬레이션할 수 있다.
- 카드와 적 콘텐츠를 핵심 로직 수정 없이 데이터로 추가할 수 있다.
- UI, 연출, 저장 기능이 게임 규칙의 소유자가 되지 않는다.

## 계층

```text
Presentation
  화면, 입력, 애니메이션, 사운드
        ↓ 명령 / ↑ 조회 상태와 이벤트
Application
  전투 진행, 런 진행, 보상 선택 유스케이스
        ↓
Domain
  카드, 덱, 족보, 피해, 전투 상태 전이
        ↑
Data / Infrastructure
  콘텐츠 로딩, 저장, 난수 구현, 엔진 어댑터
```

의존성은 바깥 계층에서 도메인 계층을 향한다. 도메인 계층은 화면, 파일 형식, 장면 객체를 알지 않는다.

## Unity 디렉터리 초안

```text
Assets/
  Hwatu/
    Content/
      Cards/
      Enemies/
      Rewards/
    Scenes/
    Scripts/
      Domain/
      Application/
      Infrastructure/
      Presentation/
    Tests/
      EditMode/
      PlayMode/
```

- `Domain`: Unity 타입에 의존하지 않는 순수 C# 규칙
- `Application`: 전투와 런 유스케이스
- `Infrastructure`: ScriptableObject 로더, 저장, Unity 난수 어댑터
- `Presentation`: MonoBehaviour, UI Toolkit 또는 UGUI, 애니메이션과 사운드
- `EditMode`: 족보, 피해, 덱, 상태 전이 테스트
- `PlayMode`: 장면 연결과 사용자 흐름 테스트

기존 `Assets/Scripts`는 기능을 구현하면서 위 구조로 점진적으로 정리한다. 빈 `Deck.cs`는 덱 도메인 작업 시 사용자 변경 여부를 다시 확인한 뒤 이동하거나 대체한다.

## 핵심 도메인 구성요소

### CardDefinition

변하지 않는 카드 원형 데이터다. 월, 변형, 태그, 기본 보정값을 가진다.

### CardInstance

런 중 플레이어가 보유하는 실제 카드다. 원형 ID, 강화 단계, 영구 변형을 가진다.

### DeckState

드로우 더미, 버림 더미, 손패, 제출 영역을 소유한다. 섞기에는 주입된 난수 공급자를 사용한다.

### HandEvaluator

두 장의 카드로부터 족보 결과만 계산한다. 피해량이나 화면 문구를 계산하지 않는다.

### DamageCalculator

족보 결과, 카드 보정값, 공격자 상태, 방어자 상태를 입력받아 피해 계산 내역을 반환한다. 실험 중인 여러 공식을 전략으로 교체할 수 있어야 한다.

### CounterRuleResolver

족보 간 특수 상성을 판정한다. 일반 족보 서열과 특수 카운터 규칙을 분리한다.

### CombatState

플레이어와 적의 상태, 턴 번호, 현재 단계, 덱 상태를 가진다. 유효한 명령만 받아 다음 상태와 도메인 이벤트를 만든다.

### EnemyIntentProvider

적 정의와 현재 전투 상태를 바탕으로 공개할 패와 행동을 정한다. 고정 패턴과 시드 기반 선택을 모두 지원한다.

### RunState

현재 덱, 체력, 재화, 진행 노드, 보유 효과를 가진다. 첫 번째 플레이어블에서는 선형 진행만 다룬다.

## 명령과 이벤트

권장 명령 예시:

- `StartCombat`
- `RedrawCard`
- `SubmitCards`
- `ChooseReward`
- `SkipReward`
- `UpgradeCard`

권장 이벤트 예시:

- `CardsDrawn`
- `CardsSubmitted`
- `HandsEvaluated`
- `CounterTriggered`
- `DamageApplied`
- `CombatEnded`
- `RewardChosen`

UI는 명령을 보내고 이벤트를 연출한다. 이벤트를 근거로 전투 결과를 다시 계산하지 않는다.

## 결정론과 난수

- 모든 셔플과 보상 후보 생성은 명시적인 난수 공급자를 받는다.
- 전투 또는 런 시작 시 사용한 시드를 기록할 수 있어야 한다.
- 테스트에서는 고정 시드나 미리 정한 값의 가짜 난수 공급자를 사용한다.
- 프레임 시간, 시스템 시간, 전역 난수 상태를 도메인 규칙에서 직접 읽지 않는다.

## 데이터 검증

콘텐츠를 로드할 때 다음을 검사한다.

- ID 중복
- 존재하지 않는 참조 ID
- 허용 범위를 벗어난 월과 수치
- 지원하지 않는 태그
- 비어 있는 적 행동 패턴
- 도달할 수 없는 보상 항목

오류는 가능한 한 게임 시작 시점 또는 개발 검증 명령에서 한 번에 보고한다.

## Unity 데이터 경계

- 카드와 적 원형은 ScriptableObject로 작성할 수 있다.
- ScriptableObject는 읽기 전용 정의로 취급하고 전투 중 체력이나 강화 단계 같은 상태를 기록하지 않는다.
- 도메인은 ScriptableObject 대신 일반 C# DTO 또는 불변 정의 객체를 입력받는다.
- 에디터 전용 검증은 런타임 어셈블리와 분리한다.
- 씬 간 상태 전달에 전역 MonoBehaviour 싱글턴을 기본 해법으로 사용하지 않는다.

## 저장

첫 번째 플레이어블에는 영구 저장이 필수는 아니다. 저장 기능을 추가할 때는 다음을 따른다.

- 스키마 버전 포함
- 카드와 적은 고유 ID로 참조
- 런 재개에 필요한 난수 상태 또는 시드 저장
- 화면이나 엔진 객체 직접 직렬화 금지
- 마이그레이션 불가능한 데이터는 명시적으로 실패 처리

## 테스트 경계

최소 테스트 대상:

- 모든 기본 족보의 정상 사례
- 족보 충돌 시 우선순위
- 광 태그 유무
- 각 피해 전략의 예시와 경계값
- 덱이 한 바퀴 순환할 때 카드 보존
- 고정 시드 셔플 재현
- 동시 피해와 전투 종료
- 잘못된 명령 거부
- 보상 선택과 스킵

## 추가로 확정할 내용

- UGUI와 UI Toolkit 중 전투 UI 방식
- 장면과 프리팹 구성
- ScriptableObject와 JSON 중 배포 데이터 직렬화 경계
- 기본 빌드, 테스트, 린트 명령
- WebGL 화면 해상도와 입력 정책
