# 구현 계획

## 현재 상태

Unity `6000.3.21f1` 2D/URP와 WebGL 대상 프로젝트에서 한 전투의 카드 선택, 승부, 피해와 전 이전, 귀시장 화면 전환까지 구현되어 있다. 기존 일회성 카드 보상은 상점 카드 목록으로 병합하기 전 상태다.

### 구현 완료

- 카드 데이터·카탈로그와 1~10월 Normal 시작 덱을 구성했다.
- 런 덱과 전투 덱을 분리하고, 시드 셔플과 드로우·손패·버림·재순환 흐름을 구현했다.
- 손패 3장 중 2장 선택, 족보 판정·미리보기와 제출 UI를 구현했다.
- 적 패턴 공개·순환, 승부 비교, 피해와 전 이전, 다음 턴 진행 및 전투 종료를 구현했다.
- 현재 전의 텍스트·동전 더미 표시와 공격 준비·타격·피격·복귀 연출을 구성했다.
- 승리 시 카드 3장 보상, 선택·해제·확인·건너뛰기와 `PlayerDeck` 추가를 구현했다.
- 하나의 `RunSeed`에서 덱 셔플과 카드 보상 난수 스트림을 분리했다.
- 전투 승리 시 같은 씬에서 귀시장 배경으로 전환하고 전투 UI와 적을 숨기며 플레이어를 화면 중앙으로 이동한다.
- 현재 전, 전투 회차와 회차별 기본 판돈을 상단 UI에 표시한다.

### 연결·검증 필요

- 한 전투를 시작해 승리한 뒤 보상 선택·확인 또는 건너뛰기까지 전체 수동 검증
- 선택한 보상 카드가 `PlayerDeck`에 추가된 상태 확인
- 플레이어 패배와 동시 전멸 경계 상황 확인
- 공격 준비·피격 및 보상 선택 연출의 실제 조작감 확인
- WebGL 전체 빌드 산출물과 브라우저 실행 확인

현재 비교 결과는 Submit 시 턴 동안 보관되며, 타격 연출 완료 시 피해와 Money 이전에 사용된다. 전투가 끝나지 않았으면 자동으로 다음 턴까지 진행하고, 모든 적을 쓰러뜨리면 `StoreController`가 귀시장 화면 전환을 시작한다. 상점 카드 목록은 아직 `StoreController`에 병합하지 않았다.

## 다음 구현 목표: 같은 씬의 전투·상점 반복

다음 작업은 별도 맵 씬 없이 현재 전투 씬 안에서 `전투 → 상점 → 다음 전투`를 반복하는 흐름을 만드는 것이다. 기존 카드 보상 UI는 상점 상단의 카드 구매 목록으로 확장한다.

### 최소 구현 범위

- 최종 보스를 제외한 각 전투 승리 후 같은 씬에서 상점 화면을 연다.
- 상점 상단에 구매 가능한 카드 세 장을 표시한다.
- 방문별 카드 구매 가격을 순서대로 `0전`, `20전`, `40전`으로 표시하고 전을 지불한다.
- 상점 하단에 보유 카드 강화 메뉴와 카드 영구 제거 메뉴를 각각 표시한다.
- 강화와 영구 제거는 상점 방문마다 각각 한 번씩 이용할 수 있고 같은 방문에서 둘 다 이용할 수 있다.
- 카드 구매, 강화와 제거를 이용하지 않고 상점을 닫을 수 있다.
- 상점을 닫으면 같은 씬에서 다음 적과 새 `BattleDeck`으로 전투를 시작한다.
- `PlayerDeck`, 플레이어의 현재 전과 `RunSeed`는 런이 끝날 때까지 유지한다.
- 일반 전투 3회를 마치면 상점 이후 12월 비광 보스전을 시작한다.
- 보스 승리 후에는 상점을 열지 않고 런 완료 화면으로 전환한다.

### 이번 목표의 비범위와 미정 사항

- 목적지 선택 맵과 별도 맵 씬
- 절차적 맵 생성, 무작위 노드 배치와 경로 분기
- 이벤트 방, 엘리트 전투와 중간보스
- 유물과 아이템
- 상점 전용 캐릭터와 최종 상점 아트

기존에 계획했던 고정 목적지 맵은 폐기하며 첫 번째 플레이어블에서 맵 기능을 만들지 않는다.

## 다음 구현 순서

1. 런 진행 단계와 현재 전투 번호를 관리하고, 같은 씬에서 전투와 상점 화면을 전환한다.
2. `CardRewardController`의 후보 생성과 덱 추가 연결을 `StoreController`로 옮기고 기존 카드 보상 UI를 상점 상단의 구매 목록으로 배치한다.
3. 방문별 구매 횟수를 관리하고 `0전`, `20전`, `40전` 가격 표시와 전 지불을 연결한다.
4. 구매 완료한 목록 항목을 비활성화하고 여러 장 구매 또는 구매 없이 진행하는 흐름을 연결한다.
5. 상점 하단에 같은 월 카드 강화와 카드 영구 제거 메뉴를 각각 제공한다.
6. 강화·제거 비용과 최소 덱 수를 확정한 뒤 전 지불을 연결하고, 방문별로 강화 1회와 제거 1회 제한을 적용한다.
7. 상점 종료 시 현재 `PlayerDeck`으로 새 `BattleDeck`을 만들고 다음 적을 초기화한다.
8. 구매·강화·제거한 카드가 다음 전투에서 실제로 반영되는지 확인한다.
9. 플레이어 패배와 보스 승리 후 새 런 또는 완료 화면으로 전환한다.
10. 확정 규칙인 전투당 1회 카드 교체를 구현한다.
11. `전투 → 상점 → 다음 전투 → 보스` 전체 흐름과 WebGL 실행을 검증한다.

## 제출 완료 조건

- 같은 씬에서 일반 전투 3회, 각 전투 뒤의 카드 구매·강화·제거 상점과 보스전을 완료할 수 있다.
- 덱 변경과 현재 전이 이후 콘텐츠에 유지된다.
- 승리와 패배 후 새 런을 시작할 수 있다.
- 진행 불가, 카드 수 불일치와 Console 예외가 없다.
- Unity 에디터와 WebGL 브라우저에서 전체 흐름을 완료할 수 있다.
