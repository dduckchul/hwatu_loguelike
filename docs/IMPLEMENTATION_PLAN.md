# 구현 계획

## 현재 상태

Unity `6000.3.21f1` 2D/URP와 WebGL 대상 프로젝트에서 카드, 덱, 족보, 시작 손패 UI까지 구현되어 있다.

### 구현 완료

- `CardData`, `CardDefinition`, `CardInstance`, `CardType`
- `CardCatalogData`와 카드 ID 조회
- 1~10월 Normal 카드 각 한 장으로 시작 덱 생성
- `PlayerDeck`과 전투용 `BattleDeck` 분리
- 고정 시드 Fisher–Yates 셔플
- 드로우 더미, 손패, 버림 더미와 재순환
- 손패 3장 드로우
- 끗, 세륙, 장사, 장삥, 구삥, 독사, 알리, 땡, 광땡 판정
- 카드 프리팹 생성과 이미지·월·타입 표시
- 손패 부채꼴 배치
- 드로우 더미와 버림 더미 수량 표시
- 전투 시작 시 첫 손패 표시

### 아직 구현하지 않음

- 손패에서 카드 2장 선택과 제출
- 제출 후 전체 손패 버림과 다음 턴 드로우 연결
- 전투당 1회 카드 교체
- 적 데이터, 공개 패와 예상 행동
- 양쪽 족보 비교와 무승부 처리
- 피해, 전, 승패와 게임 오버
- 전투 보상 후보, 선택, 스킵과 덱 추가
- 카드 강화
- 두 번째 전투와 선형 런
- WebGL 최종 빌드 확인

## 8월 7일 1차 프로토타입 완료 기준

전체 런보다 **`전투 → 카드 보상 → 변경된 덱으로 다음 전투`**가 실제로 플레이되는 것을 우선한다.

### 반드시 완료

#### 카드 선택과 턴 진행

- 손패 3장 중 2장을 선택하고 제출할 수 있다.
- 제출 결과에 양쪽 족보와 승패가 표시된다.
- 무승부는 피해 없이 다음 턴으로 넘어간다.
- 제출한 2장과 제출하지 않은 1장을 모두 버린다.
- 다음 턴에 다시 손패 3장을 뽑는다.

#### 적과 전투

- 적은 공개된 패 2장과 예상 행동을 가진다.
- 양쪽 패를 같은 `HandEvaluator`로 판정한다.
- 승자가 패자에게만 피해를 적용한다.
- 예외적으로 양쪽 전이 동시에 0 이하면 게임 오버로 처리한다.
- 전이 0이 되면 전투 승패를 표시한다.

#### 덱빌딩 흐름

- 승리 후 카드 3장 중 1장을 선택하거나 건너뛸 수 있다.
- 선택한 `CardInstance`가 `PlayerDeck`에 추가된다.
- 변경된 덱으로 다음 전투를 시작할 수 있다.
- 같은 월 카드를 얻은 뒤 땡이 실제로 나올 수 있다.

#### 최소 검증

- 정상적인 전투 흐름에서 진행 불가나 Console 예외가 없다.
- 카드 수가 드로우 더미, 손패, 버림 더미 사이에서 보존된다.
- 적 패, 양쪽 족보, 피해, 전을 화면에서 확인할 수 있다.
- WebGL에서 프로토타입을 실행할 수 있다.

### 시간이 남으면 진행

- 전투당 1회 카드 교체
- 카드 한 장의 단순 수치 강화
- 일반 적 2~3종
- 전투와 카드 제출의 최소 애니메이션
- 피해 공식 후보 비교
- 12월 비광 보스 임시 패턴

### 8월 7일까지 하지 않아도 됨

- 일반 전투 3회와 휴식/강화를 포함한 완전한 런
- 완성된 12월 비광 보스전
- 상점, 재화, 유물, 중간보스
- 분기형 맵과 이벤트 방
- 몬스터 포획, 판매, 강화 재료 시스템
- 광 부여, 띠 부착, 월 변경 강화
- 확장 족보와 특수 상성
- 동시 적 2명의 타기팅·행동 순서, 패 은폐, 복잡한 적 AI
- 저장과 불러오기
- 최종 아트, 사운드, 고급 연출과 서사
- Unity Test Framework 기반 자동화 테스트

## 다음 구현 순서

### 1. 카드 선택과 제출

- `CardView` 선택 상태
- `PlayerHandView`에서 최대 2장 선택
- 제출 버튼 활성화 조건
- 선택한 `CardInstance` 전달

완료 조건: 손패 3장 중 정확히 2장을 선택해 제출할 수 있다.

### 2. 한 턴 종료와 다음 드로우

- 제출한 카드와 미제출 카드를 모두 버림 더미로 이동
- 손패 UI 정리
- 다음 턴 손패 3장 드로우
- 덱 수량 UI 갱신

완료 조건: 여러 턴을 반복해도 전체 카드 수가 보존되고 덱이 정상 순환한다.

### 3. 적 패와 족보 비교

- 임시 적 패 2장 공개
- 샘플 적은 `100전`으로 시작
- 에디터에서 설정한 2장 패턴 목록을 턴마다 순환
- 적 패를 `HandEvaluator`로 판정
- 플레이어와 적의 `Rank` 비교
- 무승부 처리
- 양쪽 족보 표시

완료 조건: 플레이어 승리, 적 승리, 무승부를 화면에서 구분할 수 있다.

### 4. 피해와 전투 종료

- 임시 피해 공식 한 종류
- 플레이어와 적의 전
- 승자만 패자에게 피해 적용
- 전투 승리, 패배, 동시 전멸 예외 처리

완료 조건: 한 전투를 시작부터 승패까지 끝낼 수 있다.

### 5. 카드 보상과 다음 전투

- 보상 카드 후보 3장
- 한 장 선택 또는 스킵
- `PlayerDeck.AddCard`
- 새 `BattleDeck` 생성
- 두 번째 전투 진입

완료 조건: 첫 전투 보상이 두 번째 전투의 덱에 반영된다.

## 8월 10일 제출 후보 완료 정의

- 일반 전투 3회와 휴식 또는 카드 강화 이후 보스전에 진입한다.
- 시작 덱, 전투 보상, 카드 강화가 이후 전투에 반영된다.
- 승리와 패배 후 새 런을 시작할 수 있다.
- 핵심 전투와 런 흐름을 Unity 에디터와 WebGL에서 완료할 수 있다.
- 피드백에서 지적된 진행 불가와 가독성 문제를 수정한다.
