# 구현 계획

## 현재 상태

Unity `6000.3.21f1` 2D/URP와 WebGL 대상 프로젝트에서 전투, 귀시장 카드 구매, 같은 씬의 다음 전투 준비까지 구현되어 있다. 현재 다음 전투는 씬에 고정 연결된 `EnemySample`을 재사용한다.

### 구현 완료

- 카드 데이터·카탈로그와 1~10월 Normal 시작 덱을 구성했다.
- 런 덱과 전투 덱을 분리하고, 시드 셔플과 드로우·손패·버림·재순환 흐름을 구현했다.
- 손패 3장 중 2장 선택, 족보 판정·미리보기와 제출 UI를 구현했다.
- 적 패턴 공개·순환, 승부 비교, 피해와 전 이전, 다음 턴 진행 및 전투 종료를 구현했다.
- 현재 전의 텍스트·동전 더미 표시와 공격 준비·타격·피격·복귀 연출을 구성했다.
- 귀시장 진입 시 카드 후보 세 장을 표시하고 개별 카드 클릭으로 즉시 구매해 `PlayerDeck`에 추가한다.
- 하나의 `RunSeed`에서 덱 셔플과 카드 보상 난수 스트림을 분리했다.
- 전투 승리 시 같은 씬에서 귀시장 배경으로 전환하고 전투 UI와 적을 숨기며 플레이어를 화면 중앙으로 이동한다.
- 현재 전, 전투 회차와 회차별 기본 판돈을 상단 UI에 표시한다.
- 상점 카드 가격 `0전`, `20전`, `40전`, 전 차감과 구매 완료 슬롯의 흐림·매진 표시를 연결했다.
- 귀시장에서 넘어가기 입력 시 현재 `PlayerDeck`으로 `BattleDeck`을 재생성하고 등록된 `EnemySample`을 초기화한 뒤, 전투 화면 Fade-In 완료 후 손패 세 장을 드로우한다.
- 귀시장 전체 `StoreView`와 카드 구매용 `CardStoreController`, `CardStoreView`, `CardStoreSlotView`의 책임을 분리했다.

### 연결·검증 필요

- 한 전투를 시작해 승리한 뒤 카드 세 장이 귀시장에 표시되는 전체 수동 검증
- 카드 클릭 구매 시 전 차감, 흐림·매진 표시와 `PlayerDeck` 추가 확인
- 전이 부족한 카드 클릭 시 구매되지 않는지 확인
- 넘어가기 후 구매 카드가 포함된 새 전투 덱, 초기화된 적과 Fade-In 이후 손패 드로우 확인
- 플레이어 패배와 동시 전멸 경계 상황 확인
- 공격 준비·피격과 상점 구매 표시의 실제 조작감 확인
- WebGL 전체 빌드 산출물과 브라우저 실행 확인

현재 비교 결과는 Submit 시 턴 동안 보관되며, 타격 연출 완료 시 피해와 Money 이전에 사용된다. 전투가 끝나지 않았으면 자동으로 다음 턴까지 진행하고, 모든 적을 쓰러뜨리면 `StoreController`가 귀시장 화면 전환과 카드 목록 표시를 시작한다.

## 다음 마일스톤: 스테이지별 적 로딩

구조와 책임은 `ARCHITECTURE.md`의 `확정된 스테이지 적 로딩 구조`, 필드는 `DATA_SCHEMA.md`의 `StageEncounterData`를 기준으로 한다. 이 문서에서는 구현 순서만 관리한다.

1. 현재 `EnemySample` 계층을 기준으로 `EnemyBase.prefab`과 첫 몬스터 Prefab Variant를 만든다.
2. `CombatExample`에 적 스폰 포인트를 배치한다.
3. `StageEncounterData`와 첫 스테이지 조우 자산을 만든다.
4. `EnemyEncounterController`에서 조우 로드, 기존 인스턴스 제거, 프리팹 생성과 `CurrentEnemies` 제공을 구현한다.
5. `BattleController`의 고정 적 배열을 `CurrentEnemies` 조회로 교체한다.
6. `StoreController`의 고정 적 루트 배열을 제거하고 새 적 생성 후 Fade 대상을 다시 수집한다.
7. `전투 승리 → 귀시장 → 넘어가기 → 새 적 Fade-In → 손패 드로우`를 수동 검증한다.

이번 마일스톤에서는 두 번째 동시 적 콘텐츠, 적 스케일링, 보스 전용 규칙과 최종 아트를 추가하지 않는다. 구조는 적 두 명을 허용하되 첫 조우는 적 한 명으로 검증한다.

## 후속 작업

1. 상점 강화 Controller와 대상 선택 패널
2. 상점 영구 제거 Controller와 대상 선택 패널
3. 강화·제거 비용과 최소 덱 수 확정 및 방문별 1회 제한
4. 전투당 1회 카드 교체
5. 플레이어 패배, 보스 승리와 런 완료 화면
6. 일반 전투 3회와 12월 비광 보스까지 전체 런 연결
7. WebGL 빌드와 브라우저 실행 검증

## 제출 완료 조건

- 같은 씬에서 일반 전투 3회, 각 전투 뒤의 카드 구매·강화·제거 상점과 보스전을 완료할 수 있다.
- 덱 변경과 현재 전이 이후 콘텐츠에 유지된다.
- 승리와 패배 후 새 런을 시작할 수 있다.
- 진행 불가, 카드 수 불일치와 Console 예외가 없다.
- Unity 에디터와 WebGL 브라우저에서 전체 흐름을 완료할 수 있다.
