# 구현 계획

## 현재 상태

- Unity `6000.3.21f1` 2D/URP 프로젝트가 생성되어 있다.
- 첫 대상 플랫폼은 WebGL이다.
- Unity Test Framework `1.6.0`이 설치되어 있다.
- `Assets/Scripts/Deck.cs`는 아직 비어 있다.
- 첫 번째 목표는 최종 콘텐츠 제작이 아니라 전투 규칙 검증이다.

## 8월 7일 1차 프로토타입 범위

8월 7일의 완료 기준은 전체 런 완성이 아니라 **`전투 → 카드 보상 → 변경된 덱으로 다음 전투`가 실제로 플레이되는 것**이다.

### 반드시 완료

#### 프로젝트 기반

- 핵심 코드를 둘 위치와 EditMode 테스트 어셈블리를 준비한다.
- 테스트 또는 실행에 사용할 기본 명령을 기록한다.
- WebGL에서 프로토타입을 실행할 수 있는 빌드를 한 번 이상 만든다.

#### 전투 규칙

- 1~10월 패가 한 장씩 들어간 10장 시작 덱을 생성한다.
- 덱에서 손패 3장을 뽑고 그중 2장을 선택해 제출한다.
- 제출한 패를 끗, 중간 족보, 땡, 광땡으로 판정한다.
- 적은 공개된 패 2장과 예상 행동을 사용한다.
- 임시 피해 전략 하나를 교체 가능한 구조로 연결한다.
- 플레이어와 적의 피해를 동시에 적용한다.
- 체력이 0이 되면 승패를 판정하고 전투를 재시작할 수 있다.
- 덱이 소진되면 버림 더미를 섞어 다시 순환한다.

#### 덱빌딩 검증

- 전투 승리 후 카드 3장 중 1장을 선택하거나 건너뛸 수 있다.
- 선택한 카드가 덱에 실제로 추가된다.
- 같은 월 패를 추가한 뒤 다음 전투에서 땡을 만들 수 있다.
- 최소 두 번의 전투를 이어서 플레이할 수 있다.

#### 최소 UI와 검증

- 플레이어 손패, 선택 상태, 적 패, 양쪽 체력을 확인할 수 있다.
- 제출 결과로 양쪽 족보와 피해량을 확인할 수 있다.
- 족보 판정, 덱 순환, 동시 피해의 핵심 EditMode 테스트가 통과한다.
- 정상적인 플레이 흐름에서 진행 불가 또는 크래시가 없어야 한다.

### 시간이 남으면 진행

- 카드 교체 1회
- 카드 한 장의 단순 수치 강화
- 일반 적 2~3종
- 전투 및 카드 제출의 최소 애니메이션
- 드로우 더미와 버림 더미 수량 표시
- 피해 전략 후보 3종 비교 화면 또는 시뮬레이터
- 12월 비광 보스의 임시 패턴

### 8월 7일까지 하지 않아도 됨

- 일반 전투 3회와 휴식/강화를 포함한 완전한 런
- 완성된 12월 비광 보스전
- 상점, 재화, 유물, 중간보스
- 분기형 맵과 이벤트 방
- 몬스터 포획, 판매, 강화 재료 시스템
- 광 부여, 띠 부착, 월 변경 강화
- 고도리, 월견주, 화견주 등 확장 족보
- 다수 적, 패 은폐, 복잡한 적 AI
- 저장과 불러오기
- 최종 수묵화 배경, 최종 카드 그림, 사운드와 고급 연출
- 11월·12월 서사와 튜토리얼
- 전체 데이터 검증 도구와 PlayMode 자동화

### 일정이 밀릴 때 자르는 순서

1. 연출과 아트 교체
2. 카드 강화와 카드 교체
3. 적 종류 추가
4. 보스전
5. 완전한 런 구성

전투 가독성, `전투 → 보상 → 다음 전투` 흐름, WebGL 실행 안정성은 자르지 않는다.

## 8월 10일 제출 후보 완료 정의

다음 조건을 모두 만족하면 첫 번째 플레이어블이 완료된 것으로 본다.

- 새 런을 시작하면 10장 시작 덱이 생성된다.
- 손패 3장 중 2장을 선택해 제출할 수 있다.
- 적의 패와 예상 행동이 제출 전에 보인다.
- 플레이어와 적의 족보가 같은 판정기로 계산된다.
- 선택한 피해 전략으로 양쪽 피해가 동시에 적용된다.
- 덱이 소진되면 버림 더미를 결정론적으로 섞어 순환한다.
- 전투 승리 후 카드 선택 또는 스킵이 가능하다.
- 같은 월 패를 추가한 뒤 땡을 만들 수 있다.
- 카드 한 장을 단순 강화할 수 있다.
- 일반 전투 3회와 휴식/강화 단계를 거쳐 보스전에 진입한다.
- 승리와 패배 후 새 런을 시작할 수 있다.
- 핵심 규칙 테스트가 통과한다.

## 마일스톤 0: 기술 기반 확정

### 목표

Unity 프로젝트의 코드 경계, 테스트 어셈블리와 검증 명령을 확정한다.

### 작업

- `Assets/Hwatu` 아래 소스, 콘텐츠, 테스트 디렉터리 생성
- 도메인, 애플리케이션, 인프라, 프레젠테이션 어셈블리 경계 확정
- EditMode와 PlayMode 테스트 어셈블리 생성
- 테스트 러너 연결
- 기본 실행과 테스트 명령을 `AGENTS.md`에 추가

### 완료 조건

- 빈 프로젝트가 대상 플랫폼에서 실행된다.
- 자동화된 예제 테스트 한 개가 통과한다.
- 새 에이전트가 문서만 보고 실행과 테스트 명령을 재현할 수 있다.

## 마일스톤 1: 전투 규칙 코어

### 목표

화면 없이 전투 한 턴과 덱 순환을 검증한다.

### 작업 단위

1. 카드 정의, 카드 인스턴스, 시작 덱
2. 족보 판정기
3. 덱 드로우, 제출, 버림, 재순환
4. 피해 전략 3종
5. 특수 상성 판정 인터페이스
6. 전투 상태와 명령
7. 고정 패턴 적
8. 시드 기반 전투 시뮬레이터

### 완료 조건

- 기본 족보 테스트가 통과한다.
- 같은 시드와 입력으로 같은 로그가 생성된다.
- 피해 전략별 결과를 동일한 전투 표본으로 비교할 수 있다.
- 동시 피해와 전투 종료가 테스트된다.

## 마일스톤 2: 전투 화면

### 목표

한 번의 전투를 시작부터 종료까지 직접 조작할 수 있다.

### 작업 단위

1. 전투 상태 표시
2. 손패 3장 표시와 2장 선택
3. 적 패와 예상 행동 표시
4. 제출과 결과 공개
5. 족보 및 피해 내역 표시
6. 드로우·버림 더미 수량 표시
7. 승리와 패배 화면

### 완료 조건

- UI가 도메인 계산을 복제하지 않는다.
- 카드 선택 불가 상태와 잘못된 입력이 명확히 처리된다.
- 플레이어가 각 선택의 결과를 이해할 수 있다.

## 마일스톤 3: 짧은 런

### 목표

덱이 한 런 동안 변하고 보스전에 영향을 주는 경험을 만든다.

### 작업 단위

1. 전투 보상 후보 생성
2. 카드 선택과 스킵
3. 단순 카드 강화
4. 선형 런 진행
5. 일반 적 3종
6. 12월 비광 보스
7. 런 승리, 패배, 재시작

### 완료 조건

- 카드 중복 획득이 땡 빌드로 이어진다.
- 강화가 전투 계산에 반영된다.
- 한 런을 중단 없이 완료할 수 있다.

## 마일스톤 4: 플레이테스트와 규칙 확정

### 목표

전투 공식과 한 턴의 선택 품질을 데이터로 평가한다.

### 측정 항목

- 평균 전투 턴 수
- 턴당 평균 피해와 피해 분산
- 손패에서 의미 있는 선택지가 둘 이상인 턴의 비율
- 족보별 선택 빈도와 승률
- 보상 스킵률
- 덱 중복 수와 땡 발생률
- 플레이어가 적 의도를 카운터한 비율

### 결정 항목

- 기본 피해 공식
- 미제출 카드 처리
- 카드 교체 횟수
- 동시 전멸 처리
- 보상 스킵 혜택

결정 결과는 `docs/decisions` 아래 기록한 뒤 `GAMEPLAY.md`의 상태를 갱신한다.
