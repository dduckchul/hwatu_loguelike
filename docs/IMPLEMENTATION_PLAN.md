# 구현 계획

## 현재 구현

- 1~10월 Normal 시작 덱과 40장 카드 카탈로그
- 시드 기반 전투 덱 셔플, 드로우·손패·버림·재순환
- 손패 3장 중 2장 제출과 전투당 한 번 1장 교체
- 족보 판정·미리보기, 적 공개 패와 승부 비교
- `쌍띠`·`쌍열끗` 태그 판정과 승리 피해 `+5전`
- 회차별 판돈, 피해 계산과 전 이전
- 공격 준비·타격·피격·복귀 및 Idle 애니메이션
- 상단의 현재 전, 전투 회차, 판돈과 귀시장 제목
- 같은 씬의 전투/귀시장 배경·UI·적 Fade 전환과 플레이어 이동
- 카드 후보 3장, `0전 → 20전 → 40전` 즉시 구매와 매진 표시
- 귀시장 종료 시 현재 `PlayerDeck`으로 전투 덱 재생성
- `StageEncounterData`와 적 프리팹 기반 조우 교체
- `EnemyBase`, `Rorni`, `Goni`와 1·2스테이지 조우·패턴 데이터
- 전투 화면 Fade-In 이후 손패 3장 드로우

## 현재 한계

- 씬의 조우 순서는 1·2스테이지만 등록되어 있다.
- 모든 조우에서 승리하면 상점을 여는 구조라 2스테이지 뒤에도 상점이 열리며, 그 상태에서 넘어가면 존재하지 않는 다음 조우를 요청한다.
- `RunRandomProvider.BeginRun(seed)`은 있지만 새 런 시작 UI와 전체 초기화에는 연결되지 않았다.
- 플레이어 패배와 마지막 전투 승리 결과 화면이 없다.
- `StoreView`의 강화·제거 요청은 실제 Controller나 패널에 연결되지 않았다.
- WebGL 산출물의 최신 코드 기준 전체 흐름은 검증되지 않았다.

## 남은 작업

### P0: 완주 가능한 데모

1. 3스테이지 적 프리팹, 패턴과 `StageEncounterData`를 작성한다.
2. 현재 조우가 마지막인지 판정해 상점 대신 런 완료로 분기한다.
3. 플레이어 패배와 런 완료 화면을 연결한다.
4. 새 런에서 플레이어 전, 덱, 난수 스트림과 조우 순서를 초기화한다.
5. `전투 1 → 상점 → 전투 2 → 상점 → 전투 3 → 런 완료`를 검증한다.

### P1: 적 밸런스

1. 2·3스테이지의 시작 전과 패턴을 조정한다.
2. 목표 승률, 평균 턴 수와 전 잔량을 반복 플레이로 기록한다.
3. 회차별 판돈과 적 패턴 중 무엇을 조절할지 결정한다.

### P2: 상점 성장

1. 강화 Controller와 대상 선택 패널을 만든다.
2. 제거 Controller와 대상 선택 패널을 만든다.
3. 방문별 각각 1회 제한을 연결한다.
4. 강화·제거 비용과 최소 덱 크기를 플레이테스트로 확정한다.

### P3: 제출 품질

1. 공격·피격, 귀시장 전환과 버튼 조작감을 점검한다.
2. 전 부족 구매, 드로우 재순환과 마지막 조우 등 경계 상황을 확인한다.
3. Unity Console 오류 없이 전체 런을 반복 완료한다.
4. WebGL 빌드 후 브라우저에서 전체 흐름을 검증한다.

## 제출 완료 조건

- 같은 씬에서 일반 전투 세 번과 사이의 귀시장을 진행할 수 있다.
- 구매·강화·제거 결과와 현재 전이 다음 전투에 유지된다.
- 마지막 승리와 플레이어 패배 후 새 런을 시작할 수 있다.
- 진행 불가와 Console 예외가 없다.
- Unity 에디터와 WebGL 브라우저에서 전체 흐름을 완료할 수 있다.
