# 구현 계획

## 현재 상태

Unity `6000.3.21f1` 2D/URP와 WebGL 대상 프로젝트에서 한 전투의 카드 선택, 승부, 피해와 전 이전, 카드 보상 선택까지 구현되어 있다.

### 구현 완료

- 카드 데이터·카탈로그와 1~10월 Normal 시작 덱을 구성했다.
- 런 덱과 전투 덱을 분리하고, 시드 셔플과 드로우·손패·버림·재순환 흐름을 구현했다.
- 손패 3장 중 2장 선택, 족보 판정·미리보기와 제출 UI를 구현했다.
- 적 패턴 공개·순환, 승부 비교, 피해와 전 이전, 다음 턴 진행 및 전투 종료를 구현했다.
- 현재 전의 텍스트·동전 더미 표시와 공격 준비·타격·피격·복귀 연출을 구성했다.
- 승리 시 카드 3장 보상, 선택·해제·확인·건너뛰기와 `PlayerDeck` 추가를 구현했다.
- 하나의 `RunSeed`에서 덱 셔플과 카드 보상 난수 스트림을 분리했다.

### 연결·검증 필요

- 한 전투를 시작해 승리한 뒤 보상 선택·확인 또는 건너뛰기까지 전체 수동 검증
- 선택한 보상 카드가 `PlayerDeck`에 추가된 상태 확인
- 플레이어 패배와 동시 전멸 경계 상황 확인
- 공격 준비·피격 및 보상 선택 연출의 실제 조작감 확인
- WebGL 전체 빌드 산출물과 브라우저 실행 확인

현재 비교 결과는 Submit 시 턴 동안 보관되며, 타격 연출 완료 시 피해와 Money 이전에 사용된다. 전투가 끝나지 않았으면 자동으로 다음 턴까지 진행하고, 모든 적을 쓰러뜨리면 카드 보상 화면을 연다.

## 다음 구현 목표: 목적지 선택 맵

다음 작업은 고정된 일방향 경로를 맵에 표시하고, 플레이어가 현재 도달 가능한 다음 장소로 진입하는 흐름을 만드는 것이다.

### 최소 구현 범위

- `일반 전투 3회 → 상점 → 보스`의 고정 노드를 맵에 표시한다.
- 완료한 노드 바로 다음의 노드만 선택할 수 있다.
- 노드를 선택하면 해당 전투 또는 상점으로 진입한다.
- 콘텐츠 종료 후 맵으로 돌아오고 다음 노드를 연다.
- `PlayerDeck`, 현재 전과 `RunSeed`를 화면 전환 뒤에도 같은 런 상태로 유지한다.
- 이미 방문한 노드, 현재 선택 가능한 노드와 잠긴 노드를 화면에서 구분한다.

### 이번 목표의 비범위와 미정 사항

- 절차적 맵 생성과 맵 난수 스트림
- 무작위 노드 배치, 층 구성과 경로 분기
- 이벤트 방, 엘리트 전투와 중간보스
- 최종 맵 아트와 이동 애니메이션

절차적으로 생성되는 분기형 맵은 고정 일방향 런을 완성한 뒤 확장한다.

## 다음 구현 순서

1. 런 상태를 화면 전환과 관계없이 유지하고, 보상 종료 후 맵으로 이동한다.
2. 고정 일방향 노드와 방문·선택 가능·잠김 상태를 표시하는 최소 맵을 구현한다.
3. 전투 노드 진입 시 현재 `PlayerDeck`으로 새 `BattleDeck`을 만들고, 보상 카드가 실제로 드로우되는지 확인한다.
4. 전투 승리·패배 결과 UI와 맵 복귀 또는 새 런 전환을 연결한다.
5. 상점에서 같은 월 카드 강화와 카드 영구 제거를 제공하고, 비용과 최소 덱 수 제한을 적용한다.
6. 확정 규칙인 전투당 1회 카드 교체를 구현한다.
7. `전투 → 보상 → 맵 → 전투/상점` 전체 흐름과 WebGL 실행을 검증한다.

## 제출 완료 조건

- 일반 전투 3회, 상점과 보스전을 맵 진행에 연결한다.
- 덱 변경과 현재 전이 이후 콘텐츠에 유지된다.
- 승리와 패배 후 새 런을 시작할 수 있다.
- 진행 불가, 카드 수 불일치와 Console 예외가 없다.
- Unity 에디터와 WebGL 브라우저에서 전체 흐름을 완료할 수 있다.
